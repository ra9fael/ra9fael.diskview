# Disk View：扫描与交互重设计

日期：2026-11-08。依据：本次两张使用截图、当前工作区源码、WizTree 官方 FAQ 和 Microsoft 文件系统文档。

本文件保留 2026-11-08 的设计方案。用户已确认方案并授权实现；2026-11-09 的原生实现与验收见 [implementation-status.md](implementation-status.md)。配套 HTML 仍是使用合成目录数据的交互原型，不会扫描本机、申请管理员权限或操作文件，演示动画的持续时间不是扫描性能预测。

## 已确认的产品决策

- 用户接受按需授权：仅独立扫描助手申请管理员权限；主界面保持普通权限。拒绝授权时继续提供普通扫描。
- 单击选中，双击进入文件夹。悬停显示临时详情，点击后详情保持。列表与图表遵循相同规则。
- 原型交付后，用户确认“严格按照这个模拟的来”，已进入真实扫描引擎、插件权限清单和原生界面的实现阶段。

## 现状：能运行，但查找、理解和回退成本仍然很高

## 扫描架构

### 双引擎及权限边界

1. 普通权限主进程拥有界面、导航、历史与可视化。
2. 已有完整快照时立即展示，并标出时间和“上次结果”；后台更新不能悄悄替换当前上下文。
3. 本地 NTFS 整盘可选“快速扫描”。用户主动触发后才请求一个短生命周期扫描助手的授权。说明访问范围与只读用途；主进程不提权，不安装常驻服务。
4. 其他文件系统、网络目录、普通文件夹、拒绝授权或快速引擎失败时，走常规枚举。UI 明确显示实际使用的模式与回退原因。
5. 普通扫描使用有上限的目录工作队列，按设备能力调节并发；不得简单为每个目录创建线程。通过基准决定 HDD、SSD、网络路径的队列深度。

NTFS 快速路径不能只调用 FSCTL_ENUM_USN_DATA 就宣称得到完整空间统计。USN_RECORD_V2 提供文件标识、父标识、名称、属性和变化信息，并不包含文件逻辑大小或分配大小。需验证 MFT 元数据读取/解析路径，或者补充大小查询并测量其开销。优先做小型扫描引擎原型，验证准确率和性能，再定生产实现。

构树使用文件标识与父标识、紧凑节点存储和字符串池；路径只在展示/检索时拼接。处理硬链接的多路径关系，逻辑与已分配大小分开；跨卷重解析点、稀疏文件、压缩、ADS 和受保护目录都需要测试，不能把快读到的记录数量当成完整准确率。

### 快照、增量与进度

- 完整快照与正在扫描的工作树分离。完成后原子发布；取消时保留旧快照。若没有旧快照，可以保留“未完成”的局部结果，但不能将它标记为扫描完成。
- 只有确实已知的阶段总量才给百分比；目录枚举总量未知时显示不定进度、已发现文件数、耗时和当前目录，不编造 ETA。
- 局部结果允许浏览，但标注“未完成；占比以当前已发现内容为基准”。不能拿已扫描字节 / 磁盘已用字节当作扫描完成度。
- 渲染工作树快照建议 250–500 ms 一次，导航和悬停不等待扫描线程；正在浏览的图不要每条记录都重排。
- 后续以 volume identity、journal ID、checkpoint 为缓存校验依据，使用 USN 日志更新脏目录和大小。日志缺失/回卷、标识变化或无法覆盖全部变化时重建；不能把日志当成完整操作重放。

### 性能验收

先记录当前实现与候选引擎的首次结果时间、总时长、峰值内存、主线程卡顿、扫描取消延迟；对同一 NTFS 卷、同一权限、同一排除规则做冷热缓存对照。和 WizTree 比较时同时核对统计口径和是否使用管理员权限。

界面目标为导航/选择可感知响应小于 100 ms、悬停浮层约 250 ms 出现、扫描中窗口持续响应。这是设计目标，尚非实现结果；整盘速度不预先承诺为多少秒或提升多少倍。

## 交互约定

### 导航

- 顶部地址始终代表正在浏览的位置，扫描根单独显示。
- 后退/前进是浏览历史；上一级是目录父级；二者不是同一个操作。
- 点击面包屑直接回到任意祖先。过长时折叠中间层但保留根、父级、当前层，并提供可访问的完整路径编辑。
- Ctrl+L 切换可编辑路径；Enter 跳转到已索引位置；Esc 退出输入。未索引位置应明确给出“扫描此路径”动作，不能输入即偷偷扫描。
- 双击目录或点“进入文件夹”进入；双击文件保留详情，不隐式启动外部程序。Alt+Left/Right 浏览历史，Backspace 或 Alt+Up 回父级；文本框内不拦截编辑按键。

### 识别和选择

- 悬停立即高亮图表和同一列表行；浮层延迟显示，包含名称、完整路径、类型、大小、当前范围占比。
- 鼠标移动只移动浮层，不反复重排图表；浮层自动避开边缘。
- 单击将详情固定。鼠标移走后选中状态保留，不将“悬停”误当“选中”。
- 在最大文件列表选中某条，可“定位到所在目录”，图表随之显示该文件并保留选择。
- 色彩表示文件类别，辅以图例和文字；不以颜色作为唯一信息。灰色块或未知大小不代表空目录。

### 显示尺度

- 初始一层总览，用户需要时展开两层。嵌套层保留父目录标题和独立可点击区域。
- 小项聚合后保持其真实总面积，显示“其他 N 项”；展开通过列表或进入其所在目录进行，不能把省略面积摊给大文件。
- 图表与列表共享范围和选择，尺寸比例可调；窄窗用视图切换保持合理命中大小。
- 逻辑大小与占用空间必须标明来源及精度。原型使用合成逻辑大小；真实版原先的 allocApprox 只能标为近似。

## 原型体验清单

1. 悬停 C:\ 下的“用户”：浮层显示路径，底部状态同步。
2. 单击选中，再双击进入；依次进入 renfei、下载；点击顶部 C:\ 返回。
3. 试后退、前进、上一级和 Ctrl+L；输入 C:\用户\renfei\下载。
4. 切换方块/圆盘、展开层级、列表“当前层/最大文件”、排序和列表筛选。
5. 选中一个最大文件，再“定位到所在目录”。
6. “重新扫描”进入按需授权演示；分别试快速扫描、普通扫描回退和取消。
7. 扫描时切换上次结果/本轮局部结果；取消后观察数据来源标签。
8. 底部原型场景可进入首次扫描、普通扫描、失败；“问题”显示无法读取的样例目录。
9. 缩窄窗口或切换深浅主题。原型不调用 Windows 提权、文件打开、删除或真实扫描接口。

## 实施顺序

1. P0：导航模型、选中状态、完整路径提示、目录层级控制、可调整布局、扫描来源/失败/取消状态。独立于快速引擎，可先交付。
2. P1：性能基线与 NTFS 只读助手技术验证；大小/硬链接/重解析点正确性测试；再接权限声明、受限 IPC 和双引擎回退。
3. P2：快照持久化、USN 增量更新、虚拟列表与百万条目内存优化。每一步均以正确性和同范围基准验收。

## 原型验证结果

2026-11-08 使用 Edge 浏览器验证独立 HTML：悬停、选中、双击进入、面包屑、历史、路径输入、最大文件定位、方块/圆盘、分隔条、筛选排序、模拟授权/回退、局部结果、取消、失败保留旧结果和完成状态均通过。检查了 760、666、390、320 像素宽度，无页面横向溢出；浏览器未报告脚本错误，也未发出 HTTP(S) 请求。

已人工检查悬浮提示、深层导航、两层方块、圆盘、深色主题和窄窗口截图；修正了首次扫描后筛选框未清空及深色产品界面下外部演示区文字对比度问题，并针对这两项复核。以上只验证原型交互，不构成生产插件的性能或正确性验收。
