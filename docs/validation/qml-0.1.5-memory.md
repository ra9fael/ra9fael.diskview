# 0.1.5 扫描内存修复

用户在已安装的 0.1.4 报告“扫描中断：bad allocation”，后续确认 C: 快扫读取至中途失败。未运行相同权限下 C: 全盘复现，不能断言已消除该用户场景。

定位到进程内 MFT 合并沿用原跨进程 helper 的高峰内存结构：原始条目、逐条哈希节点、复制名称和结果树同进程并存。

- visited 从逐条分配的 `unordered_set<size_t>` 改为每条记录一个字节的数组。
- QML 最终合并可接管条目名称，避免保留输入与结果的两套字符串；原生版默认非消费接口保留。
- 内存不足显示中文说明而不是裸 `bad allocation`。
- 中段读取改为分段 deque 存储，避免 vector 扩容时新旧大数组并存。
- MFT sink 允许消费批次；原先 `std::move(const Entry&)` 实际仍复制文件名，现在真正转移字符串分配。
- 快扫不再构建后台目录树预览，仅发布计数/进度；最终完成后显示目录树，消除预览树与持续增长的读取记录并存。
- 新增长文件名地址转移、十万条增长地址稳定性测试，通过。非消费的原生读取回调仍兼容。
- 新增消费/非消费合并对比回归，校验目录、文件名、计数、大小和孤立记录；扫描测试通过，插件 DLL 构建通过。

未运行管理员全盘内存峰值实测，未替换/重启用户 WinShun，未安装此修复包。C: 快扫需要修复包安装后的针对性复测。
