# 0.1.14 快扫两遍读取：精确预留

0.1.13 仍在 C: 报 `MFT fast scan exceeded available memory...`。剩余峰值来自
**几何扩容**：名字缓冲和每条列在最后一段增长时，会同时持有旧块与新块（旧块
还可能接近一半容量）。几百万节点时，仅名字缓冲的这一次扩容就可能数百 MB。

## 改法

`scanToFlat` 改为两遍读取：

1. **计数遍**：只统计名字条数、名字字符总数、基础记录条数，不保存任何内容；
   期间照常发布进度并响应暂停/取消。
2. **填充遍**：按精确数量 `reserve` 所有列和名字缓冲，再填入。

名称缓冲与各列从此**不再扩容**，去掉了扩容瞬间的旧块 + 新块双份占用。

附带：

- 扩展记录名的尺寸在输出前一次性解析，随后释放 `baseSizes`（每记录 16 字节）；
- DFS 不再做逐节点二分查找，也不会再统计未知尺寸；
- 节点标志新增“尺寸已知”位，目录/时间戳位保持不变。

## 代价

C: 卷的 MFT 读两遍。按用户“可以牺牲速度”的要求，这是用时间换内存。

## 未验证

没有在用户当前 WinShun 上实测 C: 全盘。若仍失败，剩余峰值主要是“源名字 +
输出名字”同时存在；下一步会把源名字改成按块存储并在输出后按块释放，或第三遍
读取直接写入输出缓冲。
