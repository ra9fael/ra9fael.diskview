# 0.1.8 快扫内存：减半条目并去拷贝交接

0.1.7 已不再误触发普通重扫，但 C: 仍在“建目录索引”处报
`MFT fast scan exceeded available memory...`。宿主 `memoryMB` 硬上限为 2048
（`src/plugin/Manifest.cpp`，64..2048），不能靠调大额度解决。

## 本次削减

1. **读取条目减半**：`mft::read` 为每条记录产生一个空名“载体”条目和一个名字
   条目。扁平构建只需要名字，空名条目的 `(记录号, 大小)` 另存为 12 字节对，
   构建时填入按记录索引的大小表。C: 上直接少一半 `Entry`。
2. **去掉临时节点数组**：不再把名字搬进 `TempNode`，直接以读取条目为节点，
   记录号索引父条目，配 CSR 子表。少一份每节点结构。
3. **名字随输出释放**：DFS 写出一个节点后立即把它的 `wstring` 缓冲交还，
   同时释放基础大小对、父表、子表、访问位。
4. **完成结果按指针交接**：`ScanService` 不再把 `FlatTree` 作为信号参数复制
   进队列事件；改为存放 `shared_ptr` 并通过 `takeFinishedTree()` 由
   `QmlHost` 直接 move 给模型，避免整棵树在 GUI 线程再复制一次。

## 验证

- 扫描单测：父先子后、根合计、目录大小、嵌套名称、排除子树、扩展记录名用
  基础记录大小补齐；通过。
- 模型单测、真实扫描自检、Dock 与两种图表截图检查通过。
- 未在用户当前 WinShun 上实际跑 C: 全盘；需安装后复测。
