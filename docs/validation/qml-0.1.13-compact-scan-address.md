# 0.1.13 快扫紧凑累积 + 地址栏重做

## 0.1.12 仍在 C: 报内存不足

0.1.12 之后，C: 快扫仍在 `buildFlat` 撞到 2 GB 上限。原因是读取阶段仍为每个
名字保留一个 `mft::Entry`（约 72 字节结构 + 独立的 `std::wstring` 堆块），
之后才在 DFS 中释放；几百万节点时光这部分就占数百 MB。

### 改法

读取批次直接写入紧凑列，不再保留 `Entry`：

- 每节点：记录号 4、父记录 4、逻辑大小 8、修改时间 4、属性 2、标志 1、
  名字结束偏移 4，共约 **27 字节**；
- 名字字符写进一条连续 `QVector<QChar>`，DFS 输出时按切片拷贝，不再为每个
  名字构造 `QString`/`wstring`；
- 父记录查找：MFT 密集时用记录号直接索引（4 字节 × 记录数）；稀疏时退化为
  排序后的 `(记录号, 节点)` 二分，避免按最大记录号分配大表；
- 排除目录时只为目录拼完整路径（文件不可能匹配目录排除项）；
- 输出名字表预留字符容量，避免扩容时的瞬时双份。

代价是父查找可能从 O(1) 变成 O(log n)，以及少量额外排序；这是用户允许的
“牺牲速度换内存”。

### 说明

未在用户当前 WinShun 上实测 C: 全盘；这次按每个名字的实际存储量估算，预期
比 0.1.12 少几百 MB。若仍失败，需要用户提供任务管理器里的内存峰值以继续。

## 地址栏重做

- 新增“位置”菜单：列出本机固定磁盘，显示可用/总量；选中即开始扫描。
- 路径框保持可编辑，回车直接扫描。
- 新增“浏览文件夹”按钮，调用系统文件夹选择器；选中即填入并开始扫描。
- 路径框、按钮统一 28 px 高度，紧凑排列。

系统选择器使用 `SHBrowseForFolder`（GUI 线程按需 `CoInitializeEx`），不依赖
宿主是否打包 QtQuick.Dialogs。

## 验证

- 扫描单测（紧凑累积、扩展记录名用基础大小补齐、排除子树）通过。
- 自检新增“位置菜单至少有一个磁盘”检查，通过。
- 真实扫描自检、Dock 检查通过。
- 地址栏截图检查：位置菜单、路径框、浏览按钮、扫描按钮布局正常。
